# 数学建模 Skill（国赛 + 美赛）

## 概述

**这是一个教学辅助型 skill，不是论文代写工具。**

用户给出题目后，AI 引导用户从问题分析到论文完成的完整过程。每个阶段由独立子 agent 执行关键产出，主 agent 做调度与教学引导。每个环节解释「是什么 → 为什么 → 怎么做 → 学习途径」，确保用户学完后能基于指引写出自己的论文。每个产出物经过 Loop Engineering（生成→审阅→修改→再审）直到无问题才交付。

**核心原则：**
- 教学优先：每个推荐必须包含「是什么 → 为什么 → 怎么做 → 学习途径」四段式
- 只建议不改动（打磨空间）：用户主动进入打磨空间时，AI 只提建议，不 touch 任何文件
- 绝不代用户做模型选择（只推荐和分析，不下决定）
- 宁少勿假（参考文献必须真实）
- 每个阶段必须有质量门，未通过不进下一阶段
- 记录 AI 交互以备国赛 AI 工具披露要求

## 触发条件

**自动检测：** 用户输入中出现以下关键词时询问是否启用：
- 国赛 / CUMCM / 全国大学生数学建模竞赛
- 美赛 / MCM / ICM / 美国大学生数学建模竞赛
- 数学建模 / 建模竞赛 / 数学建模论文
- 题目包含明显的建模问题描述（有约束条件、目标函数、数据集等）

**手动触发：** 用户输入 `/math-modeling`

**切换提示：**
> 检测到数学建模场景，是否切换至数学建模工作空间？
> 当前检测：国赛 / 美赛 / 通用模式

## 五阶段工作流

### Phase 0：初始化（子 agent）

子 agent 使用 `references/agent-prompts/phase0-init.md` 模板，完成：
- 比赛模式检测（国赛/美赛/通用）
- 技术栈检测与确认（Python/MATLAB/LINGO/R）
- 依赖 skill 扫描（subagent-driven-development、dispatching-parallel-agents、verification-before-completion）
- 需求确认（题目理解、方法偏好、数据情况、输出要求）

依赖缺失时的报告格式（每个缺失项单独说明）：

> 推荐安装 [skill/插件名]
> 功能：[一句话]
> 为什么需要：[在哪个阶段做什么用]
> 安装方式：/plugin install [name]@[source]（仅项目目录）
> 是否安装？(Y/n)

初始化完成后输出状态报告，定位为教学辅助。

**Phase 过渡：** 完成本阶段后，将初始化结果写入 `.claude/math-modeling/checkpoint.json`。下个 Phase 启动时先读取该 checkpoint，确保状态连续。

### Phase 1：问题分析（子 agent）

子 agent 任务：
- 读题拆解：分解为子问题，明确目标/约束/变量
- 提出假设清单：每条附带合理性说明 + 不满足后果 + 放松的影响
- 数据需求分析：需要什么数据、格式、获取途径
- 已给数据则检查分布/缺失值/异常值

质量门：
- 子问题拆解是否完整？
- 每个假设是否都有合理性论证？
- 数据需求是否明确定义？

交付物：问题分析报告

Loop：生成 → 审阅 → 修改 → 用户确认

**Phase 过渡：** 完成本阶段后，将问题分析摘要写入 `.claude/math-modeling/checkpoint.json`（子问题列表 + 假设清单 + 数据需求）。

### Phase 2：模型设计（子 agent）

子 agent 任务：
- 对每个子问题提出 2-3 种候选模型方案
- 每种方案同时提供 AI/CS 风格 和 统计/数学风格对比
- 每种方案包含：

```
方案对比：[方法名]
- 它解决什么问题：[一句话]
- 为什么适合本题：[问题特征匹配模型特点]
- 优点：[2-3 点]
- 缺点/局限：[2-3 点]
- 和方案 B 比：[关键差异]
- 想深入学习：[B站/知乎/教材/慕课]
```

- 选定方案 + 完整数学表达（LaTeX 公式 + 变量定义）
- 看不懂就补通俗解释 + 学习资源推荐

质量门：
- 是否提供了至少 2 种对比方案？
- 是否说明了 Why 而非只是 What？
- 数学表达是否完整？
- 是否提供了学习路径？

交付物：模型设计方案

**Phase 过渡：** 完成本阶段后，将选定方案摘要写入 `.claude/math-modeling/checkpoint.json`（每个子问题的选定模型 + 数学表达 + 学习资源）。

### Phase 3：建模实现（子 agent）

子 agent 任务：
- 按选定方案和技术栈生成可运行代码
- 完整的注释和依赖声明
- 运行调试 + 结果可视化
- 子 sub-agent 审查代码质量

质量门：
- 代码是否可运行？
- 依赖声明是否完整？
- 结果是否合理（数量级 + 边界检查）？
- 可视化是否符合规范？

交付物：代码包（源代码 + 依赖声明 + 运行说明 + 图表）

**Phase 过渡：** 完成本阶段后，将实现结果摘要写入 `.claude/math-modeling/checkpoint.json`（代码可运行状态 + 核心数值结果 + 图表清单）。

### Phase 4：论文写作（子 agent）

子 agent 任务：
- 按比赛模板生成初稿
- 引用管理硬规则：
  - 每篇参考文献必须真实存在，禁止编造
  - 宁少勿假：5 篇真实 > 20 篇编造
  - 每处引用在交互时说明"引用了什么内容 + 为什么引"
  - 用户有疑问时提供验证方式（DOI/Google Scholar）
- 摘要按"数据来源→模型方法→核心结论→灵敏度→意义"递进
- 摘要最后一段包含灵敏度/稳健性分析总结
- **摘要黄金比例：方法篇幅:结果篇幅 ≤ 1:1，每段至少 1-2 个量化结果**
- **关键词策略：全部选用模型名/方法名（自创模型名 > 经典模型名 > 方法名 > 问题领域），禁用"优化""研究""分析"等通用词**
- **美赛 Summary Sheet 必须包含：Problem Chosen、Team Number（占位）、标题（比喻+实质双段式）、正文 250-350 词、Keywords**
- 每段正文至少一句人话解读（去 AI 痕迹）
- 每个模型选择回答 Why 而非 What
- 每张图表后至少有 1 段分析文字
- 公式：引导句→公式→释义

**图表硬规则（来自多篇 O 奖论文分析）：**
- **编号一致性**：代码中不硬编码图编号（用文件名编码如 `fig_q1_result.pdf`），编号由 LaTeX 的 `\caption` 管理
- **每张图/表必须在正文中有显式引用**（`Figure X` / `Table X`），引用率必须 100%
- **配色**：蓝(#1f4e79)-橙(#ed7d31)互补主色，色盲友好，避免红绿对比
- **三线表**：顶线粗、表头下细线、底线粗，无竖线；数字右对齐保留一致小数位
- **图标题统一**：`Figure X: Sentence case caption.`（句首大写，末尾句点）
- **坐标轴必有物理量+单位**

质量门：
- 摘要结构是否完整（方法:结果 ≤ 1:1、每段有数值）？
- 关键词是否全为模型/方法名？
- 是否有明显 AI 痕迹段落？
- 每张图表是否有分析文字？
- **每张图/表在正文中是否有显式引用？（引用率 100%）**
- 参考文献是否真实？每篇是否有出处说明？
- 国赛→流程图而非伪代码
- 假设每条附论证
- 章节间有过渡句
- **全篇公式有编号+引导句？**
- **全文术语一致？**
- **正文页数下限**：3 个问题 >= 28 页，5 个问题 >= 30 页
- **图表透明性**：每张图标注「图类型 + 所用库 + 实现方式」
- **流程图**：优先 TikZ，不能实现时附手搓教程
- **AI 交互记录**：记录每次 AI 交互以备披露

交付物：论文初稿

**Phase 过渡：** 完成本阶段后，将论文状态摘要写入 `.claude/math-modeling/checkpoint.json`（章节完成度 + 图表清单 + AI 交互记录）。

### Phase 5：最终验证（子 agent）

子 agent 任务：
- 结果合理性检查（数量级/单位/边界）
- 灵敏度分析（参数 + 权重双维度）
- 格式规范终检（按比赛要求）
- 完整性检查
- 图表终检

质量门：
- 结果是否合理（数量级 + 单位 + 边界 + 极端情况）？
- 灵敏度是否覆盖参数和权重两个维度？有图表支撑？
- 格式是否符合比赛要求？
- 所有图表是否有连续编号？代码编号与 LaTeX 引用对齐？
- 图/表在正文中引用率是否 100%？
- 所有公式是否有编号和引导句？
- 全文术语是否一致？
- 推荐策略是否可执行？
- 参考文献完整且真实？每篇在正文中有引用？
- 美赛：25 页以内、AI 报告、Memorandum、目录页、独立 Assumptions、符号表？
- **正文页数是否达标**（国赛 3 问 >= 28 页，5 问 >= 30 页）？
- **每张图是否有实现说明**（图类型 + 库 + 实现方式）？
- **流程图是否为 TikZ 或附了手搓教程**？
- **AI 交互记录是否完整**（时间 + 提问 + 回答 + 采用/修改）？

交付物：最终检查清单

**Phase 过渡：** 完成本阶段后，将最终验证结果写入 `.claude/math-modeling/checkpoint.json`（通过/不通过 + 问题清单）。

## 打磨空间

用户主动说出以下内容时，AI 立即切换至打磨空间模式：
- 「我现在要进行论文/代码打磨」
- 「进入打磨空间」
- 「帮我看看这里该怎么改」

打磨空间行为规则详见 `references/polishing-space.md`，核心原则：**只建议，不改动**。

退出打磨空间：用户说「回到正常工作流」或「继续推进」。

## 上下文压缩策略

主上下文 >70% 时触发：
1. 已完成阶段的详细日志写入 .claude/math-modeling/archive/
2. 主上下文只保留摘要（3-5 行 + 关键决策点）
3. 用户关键选择原文保留不压缩
4. 当前阶段完整上下文保留
5. 提示用户：已归档已完成阶段，继续当前阶段

## AI/CS 打法 vs 统计/数学打法

用户在 Phase 2 和所有方法推荐环节，必须列出两种风格对比：

| 维度 | AI/CS 风格（AI 学生） | 统计/数学风格（数统院） |
|------|---------------------|----------------------|
| 核心理念 | 数据驱动 | 模型驱动，先假设再验证 |
| 常用方法 | NN/SVM/GBDT/聚类 | 回归/假设检验/时序/贝叶斯 |
| 验证方式 | 交叉验证/Bootstrap | 统计检验(p值/CI)/残差 |
| 可解释性 | 黑箱+SHAP事后解释 | 模型本身可解释 |
| 编程语言 | Python | R/MATLAB |
| 适合场景 | 数据量大、模式复杂 | 数据量小、需严格推断 |

推荐时不偏袒任何一种，根据题目特征客观推荐。标注"这个和你学的 [课程概念] 相通"帮助理解。

| 问题类型 | AI/CS 推荐 | 统计/数学推荐 |
|---------|-----------|-------------|
| 分类/预测 | 随机森林/XGBoost/MLP | Logistic 回归/LDA |
| 时序预测 | LSTM/Transformer/Prophet | ARIMA/指数平滑/状态空间 |
| 聚类/分组 | K-means/DBSCAN/GMM | 层次聚类/潜在类别分析 |
| 降维 | Autoencoder/t-SNE | PCA/因子分析 |
| 因果推断 | 因果森林/反事实推理 | DID/工具变量/断点回归 |
| 优化问题 | 强化学习/遗传算法 | 线性/整数/动态规划 |

## 红线

论文红线：
- 绝不生成有明显 AI 痕迹的段落
- 绝不引用虚假文献
- 绝不在国赛正文放伪代码
- 绝不放无分析文字说明的图表
- 绝不跳过假设论证
- 绝不交付未经至少一轮审阅的产出
- **绝不让图编号与 LaTeX 引用错位（代码不硬编码编号，由 LaTeX 管理）**
- **绝不让任何一张图/表在正文中无引用（引用率必须 100%）**
- **绝不让 AI 交互记录缺失（满足国赛 AI 工具披露要求）**

建模红线：
- 绝不代用户做模型选择
- 绝不生成未经运行验证的代码
- 绝不忽略假设对结果的影响
- 绝不生成无来源的数据

流程红线：
- 绝不跳过任一质量门
- 绝不把子 agent 完整日志带入主上下文
- 绝不在缺少核心依赖时继续推进
- 绝不一次推进两个 Phase

## 快速参考：国赛 vs 美赛

| 维度 | 国赛 | 美赛 |
|------|------|------|
| 语言 | 中文 | 英文 |
| 摘要 | 中文摘要+关键词 | Summary Sheet 250-350 词 |
